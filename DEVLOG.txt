2026-07-24  Initial build (cosmic-glass weather dashboard)
---------------------------------------------------------
Goal: rebuild a weather web app from scratch to match a supplied design mock
(deep-space background, glass panels, snowy Cardiff dashboard).

Stack decision:
  - Plain HTML + CSS + vanilla JS, no build step, no dependencies.
    -> trivially deployable to GitHub Pages / Vercel, no secrets to manage.
  - Live data from Open-Meteo (free, NO API key). Covers every field in the
    mock: current, hourly, daily, UV, AQI, dew point, visibility, pressure,
    sunrise/sunset. Geocoding + air-quality are separate Open-Meteo endpoints.

Files: index.html, styles.css, app.js, README.md, assets/

Mistakes made & fixes (keep this list honest):
  1. Alert banner showed as an empty box even when no advisory applied.
     Cause: `.alert { display:flex }` overrides the HTML `hidden` attribute
     (element-level `display` beats the UA `[hidden]{display:none}` rule).
     Fix: added explicit `.alert[hidden] { display:none; }`.
  2. Layout overflowed short viewports and `body{overflow:hidden}` CLIPPED the
     bottom (7-day forecast unreachable). Content was ~1141px tall.
     Fix: switched body to `overflow-x:hidden; overflow-y:auto` (scroll fallback)
     AND tightened vertical rhythm (temp size, panel/stat margins, arc & chart
     heights, forecast row padding) -> ~1042px, fits typical laptop screens.
  3. launch.json lives in the WORKSPACE ROOT (/Users/escarlai/ClaudeCode/.claude),
     not the project folder — a per-project launch.json is ignored. Added the
     "weather-app" server there (python http.server on :5178).
  4. Manual scene override persisted across a city change, so a new city could
     show an ambiance unrelated to its real weather.
     Fix: reset `state.manualScene = null` when a city is selected, so each new
     location shows its real-weather scene; manual pick only holds for the
     current city (until next data sync).

Verified in-browser:
  - Cardiff (default) live: 18C clear, correct sunrise/sunset, trend, 7-day.
  - Search -> Ushuaia: -6C, wind-chill advisory shown, snow-showers forecast,
    city-local clock, AQI/pressure/visibility all populated. No console errors.

Notes / gotchas for future me:
  - Open-Meteo hourly/daily times are LOCAL wall-clock ISO (no 'Z'). To display
    them we parse with a forced 'Z' and read via getUTC* so we don't double-apply
    the browser's own timezone. City clock = Date.now() + utc_offset_seconds*1000,
    read with getUTC* getters.
  - Scene tabs (sunny/rain/snow/wind) = background ambiance presets; they do NOT
    fake the reported weather data (that stays real).


2026-07-24  Visual pass — real 3D-glass upgrade
-----------------------------------------------
Goal: the "glass" look was thin (flat low-opacity tiles). Push it to a proper
frosted-glass / 3D aesthetic without adding any dependency (still no build step).

What changed (CSS + a little JS, no markup logic touched):
  - Glass surface system (styles.css): a shared .card/.panel/.current recipe —
    backdrop-filter blur+saturate+brightness, layered gradient tint, 1px rim
    edge, and a 4-layer box-shadow (inner top highlight + inner bottom shade +
    two drop shadows) so panels read as floating slabs. Driven by --glass-*
    tokens in :root so the whole system is tunable from one place.
  - Two pseudo-layers per surface: ::before = frost gloss that TRACKS the pointer
    (via --mx/--my), ::after = thin specular streak that sweeps once on hover.
    Content children are forced position:relative;z-index:1 so text sits ABOVE
    the frost (z0) and BELOW the faint sheen (z3) — checked in-browser, no
    contrast/legibility regression.
  - 3D tilt (app.js initTilt): pointer-reactive rotateX/Y (max 5deg) + translateZ
    lift on the [data-tilt] surfaces, using event delegation on .dashboard so it
    also covers the JS-injected stat cards. Fully gated behind `reduced` +
    the existing prefers-reduced-motion CSS override.
  - Atmosphere: slow-drifting aurora ribbons (.bg-glow::before, 28s) behind the
    blur, plus a low-opacity SVG fractal-noise grain (body::after) to kill
    gradient banding. Cool glow on the hero temp + clock; glow on the stat bars.
  - Dropped the centre column divider (border-left) — panels now carry their own
    glass edges, so the divider fought the look. Dock/alert reskinned to match.

Honest note / tradeoff:
  - The glass padding grew the page to ~1142px tall (was ~1042). Still fine: body
    already has overflow-y:auto as the scroll fallback (see 2026-07-24 fix #2),
    and it fits taller viewports; tightened panel rhythm to limit the growth.
  - backdrop-filter blurs the animated particles BEHIND each panel — intended
    (that IS the frosted read); particles stay crisp in the gaps/margins.

Verified in-browser (localhost:8144): Cardiff live 27C clear, no console errors,
no horizontal overflow, tilt + frost-tracking + sheen all firing, stacking order
correct, and the desktop + mobile (375px) layouts both hold.


2026-07-24  Visual pass 2 — dimensional hero weather icon
---------------------------------------------------------
The hero conditions icon was the same flat SVG as the tiny forecast-row icons.
Gave the HERO one (only) real depth, leaving the small forecast icons clean.

  - New heroIcon() in app.js — parallel to icon(), same geometry/animation
    classes (so sun-spin / flake-fall / drop-fall still apply) but emits an
    SVG <defs> with radial/linear gradients + a soft ground-shadow ellipse,
    a specular gloss dot on the sun, and the wc--hero marker class. render()
    calls heroIcon() for #currentIcon; forecast rows still call icon().
  - Depth comes from CSS scoped under .current__icon: gradient fills via
    fill:url(#hg-*) (CSS beats the base solid-fill so only the hero upgrades),
    layered drop-shadow glow per condition, warm sun halo, cool moon halo.
  - Real 3D: .current already tilts (preserve-3d + perspective), so the icon
    wrapper gets translateZ(34px) to float ABOVE the glass and parallax as the
    card tilts, plus a slow heroFloat bob on the svg (both die under
    prefers-reduced-motion via the global override).

Gotcha worth remembering: an SVG element's CSS `fill` property WINS over its
`fill="..."` presentation attribute, so scoping the gradient fill in CSS
(.current__icon .wc-sun{fill:url(#hg-sun)}) is what keeps the forecast icons
flat while the hero gets gradients — no need to fork the shape markup.

Verified in-browser: hero uses wc--hero + defs + ground; sun fill resolves to
url(#hg-sun); wrapper matrix3d shows translateZ(34); all icon variants
(cloud/fog/partly/rain×3/snow×3/thunder/clear-night moon) build without error.


2026-07-27  v2 — "Windy-style" pro console rebuild
--------------------------------------------------
Goal: same data, far more capability and a professional weather-console feel
(the user asked for "有 d windy 既感覺").

What changed
  - App shell rewritten: topbar (search / place / city clock / units / tools),
    left data sidebar, MAP STAGE, docked meteogram. CSS grid, 100dvh, no scroll
    on desktop; stacks to a single column at <=1020px.
  - NEW animated wind map (the centrepiece):
      * Leaflet 1.9.4 VENDORED into vendor/ (no CDN at runtime), CARTO dark
        basemap split into `dark_nolabels` (under the weather) + `dark_only_labels`
        (over it) so place names stay readable through the colour field.
      * Real wind grid from Open-Meteo: ONE request with 12x8 = 96 coordinates,
        8 variables, 4 days hourly. Times forced to UTC so all points share an axis.
      * Canvas particle advection with fading trails, positions stored in lat/lon
        and projected with our own Web Mercator maths (matches Leaflet's EPSG:3857).
      * Six raster layers: wind / temp / rain / cloud / humidity / pressure,
        rendered at 1 sample per 4 css px into an ImageData then scaled up with
        smoothing. Pressure additionally draws marching-squares ISOBARS with labels.
      * Hover probe card (wind barb, gust, temp, rain, cloud, humidity, pressure).
      * Click anywhere on the map = full forecast for that point.
  - NEW 72-hour timeline scrubber with play/pause. Scrubbing drives the map field,
    the meteogram cursor AND the whole sidebar (index 0 = live obs, anything else
    shows a FORECAST badge with that hour's values).
  - NEW multi-track meteogram: temperature (colour-ramped curve) + apparent temp,
    pressure line on a right axis, precipitation bars (snow tinted differently)
    + probability, wind speed area + gust + direction arrows, low/mid/high cloud
    band, night shading, day dividers, hover crosshair + full readout, 24H/3D/7D.
  - Sidebar upgrades: gusts + Beaufort, 3-hour pressure tendency, moon phase
    (drawn from the illuminated-limb ellipse), AQI with PM2.5/PM10/O3/NO2 breakdown,
    day-clickable 7-day rows, geolocation, saved cities, shareable URL hash.
  - Units: °C/°F and km/h · m/s · mph · kt, both persisted.
  - Keyboard: / search, space play, arrows scrub, 1-6 layers, u w r l s m n.
  - `window.auroraWX` console handle for poking at live state.

Mistakes made & fixes (honest list):
  5. The whole page rendered UNSTYLED after the rewrite. styles.css was being
     served from Chrome's cache under HEURISTIC freshness (python http.server
     sends Last-Modified but no Cache-Control, so Chrome cached it for ~10% of
     the file's age = hours) — the CSSOM still held the OLD 123 rules.
     Fix (three parts): devserver.py now sends `Cache-Control: no-store`;
     index.html links `styles.css?v=2`; vercel.json sets must-revalidate for
     html/css/js and immutable for vendor/.
  6. Leaflet threw `Invalid LatLng object: (NaN, NaN)` from flyTo, and because
     the first animation frame runs SYNCHRONOUSLY inside flyTo the exception
     propagated into refresh()'s try/catch and showed a bogus "could not load
     live data" toast while the data was actually fine.
     Cause: flyTo divides by `getSize()`, which is 0 if the map pane has not been
     laid out when Leaflet caches `_size`.
     Fix: guard in WindMap.setPlace (fall back to setView when size is 0) plus a
     one-shot `invalidateSize()` on the frame after construction.
  7. Meteogram tracks used FIXED pixel heights (20+88+42+48+18+axis = 254px) but
     the dock only gives ~208px, so precipitation/wind/cloud were drawn below the
     visible area. Fix: track heights are now shares of the available height with
     per-track minimums, and the wind arrows got their own row.
  8. Timeline showed `--:--` and wrong day labels on boot: renderTimelineDays()
     and setTimeIndex() ran in init(), before the city's utc_offset was known.
     Fix: re-run both at the end of every successful refresh().
  9. Search results were unreadable — the `li` grid used implicit placement so
     the name/region/coords landed in overlapping cells.
     Fix: explicit `grid-area` for b / span / i.
 10. Rain (and every other) layer showed hard DIAMOND facets: plain bilinear
     interpolation is only C0, so cell corners are visible on a coarse grid.
     Fix: smoothstep the interpolation weights in Field.locate() (C1 across cell
     boundaries) and raise the grid from 10x7 to 12x8.
 11. The `·` separator dots vanished inside `.panel__head .meta` — an inline `<i>`
     ignores width/height. Fix: `.place__sep{display:inline-block}` and made
     `.meta` an inline-flex row.
 12. Topbar tools overflowed at 375px wide (sound + refresh clipped).
     Fix: smaller tools below 680px, `#soundBtn` hidden below 430px.

Merging the v1 visual passes
  The two "3D-glass" commits above landed on origin while this rebuild was in
  progress, and they targeted markup this rebuild replaced (.current, .col--*,
  the monolithic app.js). Rather than force-push over them, they were merged and
  the visual system was PORTED onto the new shell:
    - --glass-* tokens, the rim light / pointer frost / hover sheen and the
      [data-tilt] parallax now apply to .card, .pill and .aq__cell (the
      free-standing sidebar surfaces). initTilt() moved into js/app.js and
      delegates from #side so it still covers the JS-injected stat cards.
    - Map and overlay chrome (.mapcard, .layers, .timeline, .mapzoom,
      .omni__panel, .toast) deliberately keeps an OPAQUE base and takes only the
      rim + layered shadow: full frosted glass over a bright temperature or rain
      field destroys the contrast the readouts need.
    - heroIcon() moved to js/util.js and is used by panels.renderHero() for
      #currentIcon; the gradient/glow CSS is rescoped from .current__icon to
      .hero__icon. The forecast rows still use the flat icon().
    - Aurora ribbons kept; the film grain moved from z-index 4 to 1 so it sits
      UNDER the app chrome instead of veiling the map and the meteogram.

Notes / gotchas for future me:
  - An SVG element's CSS `fill` beats its `fill="..."` attribute — that is what
    lets .hero__icon swap in gradient fills while the small icons stay flat.
  - Leaflet canvases live in a custom pane ('wx', z-index 250) so labels can sit
    above them. They carry `leaflet-zoom-animated` so Leaflet's own transition
    drives the transform, and `_animZoom` applies scale+offset on 'zoomanim'.
    The canvas is drawn PAD=96px larger than the viewport so panning stays covered
    without a redraw; it is only re-anchored on moveend/zoomend/resize.
  - Particles must be stored in lat/lon, not canvas px — that way a re-anchor or
    zoom just re-projects them instead of teleporting the flow.
  - Wind u/v from speed+direction: direction is where the wind comes FROM, so
    u = -spd*sin(dir), v = -spd*cos(dir); screen y is inverted (y -= v).
  - Particle screen speed is normalised per zoom (TARGET_PX px per km/h per frame)
    so the flow does not become frantic when zoomed in; steps > MAX_STEP_PX respawn.
  - One field request is ~96 locations x 8 vars x 96 hours. Refetched (debounced
    450ms) only when the viewport leaves the current grid or zooms out a lot.
  - Scene ambiance now always follows the REAL reported weather; the old manual
    scene tabs are gone (map layers replaced them).
